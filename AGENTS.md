# AGENTS.md

Правила для Private Gateway Web. Основа — `rvburov/private-gateway-client/AGENTS.md`,
проверенный commit `cff4c9cb4c3bda2841eb1cafdf8d28fd4cfd5ea5` (содержимое совпадает
с ранее изученным `536b70e848ce02f3fe1fa2a08db2542e2761aac2`). Правила адаптированы
к веб-приложению; команды .NET, VPN-службы и платформенные тесты сюда не переносятся.

## Область проекта

- Пользователь согласовал макет v8 и разрешил разработку приложения.
- Этот сайт: презентация клиента, вход по приглашению с 2FA, скачивание клиента,
  администрирование участников и приглашений. Кабинет не управляет VPN.
- Не менять Private Gateway, VPN-сервер, профили, сетевые настройки машины или вход
  в само приложение клиента. Публикация сайта и настройка рабочего сервера — отдельный этап.
- В `mockup/` сохраняется согласованный визуальный эталон. Рабочий интерфейс — `frontend/`.
  При изменении дизайна обновлять эталон и описание решения вместе с кодом.
- Стек: Python + FastAPI, React + TypeScript + Vite, PostgreSQL, Docker и Caddy.
  Redis добавлять только при обоснованной необходимости.

## Организация работы

- В облаке работать в предоставленной копии и ветке, без дополнительного worktree.
  На общей машине — отдельный worktree для каждого чата.
- Перед работой и итогом проверить `git status --short`, ветку и отличие от удаленного master.
  Не уничтожать чужие правки, не применять `reset --hard`, `clean`, принудительное удаление веток.
- Следовать ROADMAP в README; решения записывать в `docs/roadmap/AGENT-DECISIONS.md`.
  Согласованные границы — в `docs/roadmap/DECISIONS.md`. Не спрашивать о рутинных развилках.
- Команды и инструкции разработчику — bash. Сообщения пользователю — по-русски.
- При параллельной работе закреплять непересекающиеся файлы и согласовать API до интеграции.

## Код, данные и зависимости

- Backend: маршруты разбирают запросы, сервисы выполняют бизнес-операции, модели описывают БД.
  Проверки роли, действующей сессии и отзыва доступа обязательны на сервере.
- Frontend: компоненты, API и локализация разделены; английский по умолчанию, русский доступен
  переключателем. Состояния загрузки, ошибки и клавиатурная навигация обязательны.
- Дизайн, шрифты, цвета и интервалы — из согласованного макета; общие значения в CSS-токенах.
  Новые тексты интерфейса — в словаре EN/RU, с запасом длины. В новых русских текстах писать `е`.
- Заимствование сначала записать в `docs/sources/`: точный URL файла и commit, лицензия или
  основание доступа, что адаптируется и как проверяется. Не выдавать идеи за прямой перенос кода.
- Сохранять лицензии ресурсов. Новые зависимости фиксировать в lock-файлах и реестре компонентов.
- Не переносить секреты, реальные аккаунты, пользовательские данные и настройки серверов.
  В тестах — только искусственные данные и адреса документации. Секреты не писать в Git,
  журналы, аргументы процессов или ответы пользователю; локальные файлы секретов игнорировать.
- Начальных паролей и встроенного административного аккаунта нет. Создание первого
  администратора — явная локальная команда с безопасным вводом.
- Реальные версии и ссылки на клиент не выдумывать. Пустой каталог отображается как недоступный.

## Проверки

- Перед коммитом: проверки backend, миграций PostgreSQL, TypeScript и сборки frontend,
  значимые тесты сценариев и браузерная проверка на компьютере и телефоне.
- Проверять отказ в доступе, CSRF, ограничения попыток, повторное использование одноразовых
  кодов, отзыв доступа и попытки обхода файлового каталога.
- Для новых тестов критичных границ проверять, что они обнаруживают ошибочное изменение кода.
- В отчете указывать passed/failed/skipped и причины пропусков. Локальный стенд не означает
  проверку рабочего сервера. Документацию и ROADMAP обновлять вместе с поведением.
