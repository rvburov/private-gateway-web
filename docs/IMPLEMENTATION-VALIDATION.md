В общем `scripts/check.sh` окончательно прошли 83 теста. Один промежуточный параллельный
прогон был остановлен из-за пересечения двух процессов, пересоздававших одну тестовую
базу. После остановки обоих выполнен полный последовательный прогон с результатами выше.
Браузерные проверки используют отдельную базу и не затрагивают тестовую схему unit/API.

## Что проверено по поведению

- Приглашение привязано к email и одноразовое; регистрация не дает сессию до настройки 2FA.
- Пароль, TOTP, резервные коды, доверенное устройство и сброс проходят настоящие серверные
  проверки. Повторное использование кода и параллельные административные изменения проверены.
- Участник не получает административный API. После отзыва доступа `/api/me` и загрузки
  немедленно отвечают 401; после обновления браузер возвращается на вход.
- Закрытые файлы не раздаются статикой; проверены пути, symlink, размер и доступ.
  Каталог установки остается пустым: тестовые файлы не объявляются выпуском клиента.
- Форма 2FA получает настоящий QR от API. Резервные коды показываются один раз, пользователь
  подтверждает их сохранение. Снимки не содержат паролей, QR-секретов или кодов приглашений.
- Запоздавший `/me` не отменяет более новый вход или выход. iframe клиента остается тем же
  документом при смене раздела, устройства и языка; повторных загрузок и сдвига соседнего
  текста нет. У главной сохранено выравнивание v8, вход в шапке не переносится.
- API-контейнер непривилегированный, файловая система только для чтения, порт API и БД
  не опубликован. Доступен только `127.0.0.1:8080`. Подмена X-Forwarded-For через Caddy
  не обходит лимит: после пяти отказов получен 429.

Контроль чувствительности тестов: обнаружены четыре временных backend-мутанта
(CSRF, роль, повтор TOTP, сериализация действий администратора) и три frontend-мутанта
(длина OTP, ограничение домена App Store, устаревшее сообщение клиента). Мутации не
входят в рабочие исходники. Два дополнительных теста закрывают гонку ответа `/me`.

## Воспроизведение

- `scripts/check.sh` — отдельная БД через `PGWEB_TEST_DATABASE_URL`.
- `node tests/browser-smoke.cjs` — запущенный сайт; `PGWEB_BROWSER_URL` задает стенд.
- `python3 deploy/smoke.py` — собранный локальный контейнерный стенд.
- `tests/browser-access.cjs` — только одноразовый стенд на loopback и локальная
  `.localdata/browser-fixture.json` с искусственным первым администратором `@example.test`.
  Эту проверку нельзя направлять на рабочие учетные записи. Fixture и ключи не в Git.

Скриншоты браузерных проверок сохраняются в `artifacts/browser` и `artifacts/docker-browser`,
отчеты тестов — в `artifacts/test-results`. Эти файлы игнорируются Git.

## Пределы проверки

Это проверка локального приложения, не публикация сайта и не аудит рабочего хоста.
Нативный запуск на Windows/macOS, реальный домен/HTTPS, резервное копирование и восстановление
рабочей базы не проверялись. Сборки Private Gateway Client и ссылка App Store не подключены.
В GitHub подготовлен CI с теми же основными проверками; его удаленный результат фиксируется
отдельно после отправки, локальный прогон не подменяет статус CI.
