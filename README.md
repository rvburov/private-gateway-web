# Private Gateway Web

Отдельный сайт Private Gateway Client: презентация, регистрация по приглашению,
вход по паролю (администраторам — с двухфакторной проверкой), закрытое скачивание клиента
и управление доступом к сайту.
Согласованный макет **v8** с оформлением «Спектр» сохранен в `mockup/`; рабочее приложение —
в `frontend/` и `backend/`.

VPN-сервер, подписки и подключения остаются в Private Gateway. Сайт не управляет VPN
и не реализует вход в само приложение клиента. Рабочий сайт — `https://private-gateway.duckdns.org`
на сервере AI Agent Capper; как он разворачивается — [deploy/README.md](deploy/README.md).

## Локальный запуск

Нужны Python 3.12+, Node.js 24, npm и Docker Compose. Команды выполняются из корня в bash
(Windows — Git Bash). Секреты генерируются в игнорируемый `.env.local`, не выводятся в терминал.

```bash
scripts/dev.sh setup
scripts/dev.sh db
scripts/dev.sh migrate
scripts/dev.sh admin --email you@example.com
scripts/dev.sh start
```

В команде администратора замените `you@example.com` своим адресом. Пароль вводится скрыто;
встроенных аккаунтов и начальных паролей нет. Откройте **http://127.0.0.1:5173**, войдите и
настройте приложение-аутентификатор. Сохраните показанные один раз резервные коды.

Администратор создает приглашения в своем кабинете. Они привязаны к email и используются
один раз. Участник регистрируется и входит по email и паролю, без 2FA, и видит скачивание
клиента и свои устройства. Двухфакторная проверка обязательна только администраторам: для
изменения доступа, выдачи и удаления приглашений и удаления участников администратор
подтверждает действие текущим кодом 2FA.

Ctrl+C останавливает запущенные API и Vite. `scripts/dev.sh stop-db` останавливает локальную
БД без удаления данных. Установка, контейнерный стенд, каталог файлов и эксплуатационные
границы описаны в [docs/operations.md](docs/operations.md).

## Интерфейс и загрузки

Английский выбран по умолчанию; EN/RU меняет язык без сброса полей. Главная сохраняет
согласованную композицию v8 и оригинальную кликабельную демонстрацию Private Gateway Client.
Оформление «Спектр»: цветные пятна на фоне главной, градиент бирюзовый → синий в заголовке,
кнопках, панели входа и баннере кабинета, свой цвет у каждой платформы. Палитра задана токенами
в `style.css`, правила — в `spectrum.css`; оба файла одинаковы в `mockup/` и `frontend/src/styles/`.
Демонстрация помечена отдельно: кнопки внутри нее не подключают VPN.

В кабинете пять платформ: Windows, macOS, iOS, Linux, Android. Система посетителя
определяется по User-Agent: ее карточка идет первой с основной кнопкой (неизвестная — Windows,
как раньше). Каталог изначально пуст: версии и ссылки не выдуманы, недоступные загрузки
отключены. После подключения проверенных файлов через CLI скачивание проходит через API с
проверкой сеанса и доступа; `.apk` отдается с типом для установщика Android, у карточки Android
подсказка об установке. Ссылка iOS появляется только после внесения действительного адреса App Store.

## Контроль доступа

- **Журнал скачиваний** (Администрирование → Журнал скачиваний): кто, когда, какую платформу и
  версию скачал, с какого устройства и из какой сети (IP без последних цифр).
- **Устройства** (раздел у каждого участника и в карточке участника у администратора): входы на
  сайт и устройства с приложением, кнопки «Завершить сеанс» и «Удалить устройство». Входов на сайт
  не больше 3 одновременно, новый вытесняет самый давний; устройств с приложением — 3 или личный
  лимит участника; новых устройств — не больше 3 за 30 дней (повторный вход того же устройства
  не считается). Там же «Сменить пароль» и «Выйти на всех устройствах».
- **Вход в приложение** аккаунтом сайта: участник — паролем, администратор — паролем и кодом 2FA;
  устройство привязывается к аккаунту. Блокировка, удаление участника, смена пароля или удаление
  устройства закрывают приложение при следующей проверке. Решение о доступе принимает сайт;
  VPN-сервер не меняется. Контракт — `docs/api-contract.md`.
- **Удаление и очистка**: администратор удаляет участника целиком (журнал скачиваний остается
  с «Удаленным участником») и приглашения в любом состоянии; API раз в сутки удаляет
  закончившиеся входы, старые приглашения и журналы по срокам из `docs/api-contract.md`.

## Разработка и проверки

- `frontend/` — React + TypeScript + Vite, локальные ресурсы, EN/RU и тесты интерфейса.
- `backend/` — FastAPI, SQLAlchemy, PostgreSQL, миграции Alembic, тесты сценариев и безопасности.
- `deploy/` — Docker/Caddy: локальный стенд (`compose.yml`) и рабочий сервер (`compose.prod.yml`,
  `deploy.sh`, `server-setup.sh`, бэкапы — [deploy/README.md](deploy/README.md)). Адресов
  сервера и секретов в репозитории нет.
- `mockup/` — согласованный визуальный эталон и автономный экспорт.
- [AGENTS.md](AGENTS.md) — правила работы на основе Private Gateway Client.
- [Архитектура](docs/ARCHITECTURE.md), [API](docs/api-contract.md),
  [источники](docs/sources/REUSE_REGISTER.md), [решения](docs/roadmap/AGENT-DECISIONS.md).

Для backend-тестов задайте `PGWEB_TEST_DATABASE_URL` на отдельную PostgreSQL-базу, в имени
которой есть `test`: тесты пересоздают ее таблицы. Рабочая база для тестов недопустима.

```bash
scripts/check.sh
node tests/browser-smoke.cjs
python3 scripts/generate-licenses.py
```

Браузерная проверка требует уже запущенное приложение, Chromium или установленный браузер
Playwright. `PGWEB_BROWSER_URL` меняет адрес стенда; снимки сохраняются в `artifacts/browser/`.
Проверки не используют рабочие аккаунты или VPN. Итоги текущей реализации — в
[docs/IMPLEMENTATION-VALIDATION.md](docs/IMPLEMENTATION-VALIDATION.md).
